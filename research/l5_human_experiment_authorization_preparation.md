## 1. Protocol Status [D]

### 1.1 Research Question (frozen from L5.7)

> **RQ-L5.7**: Compared with Instance Validation (A) and Naive Pattern Validation (B),
> does Evidence Aggregation + Evidence Compression + Semantic Claim Validation (C)
> reduce Human cognitive burden while preserving or improving validation quality?

### 1.2 Hypothesis (non-directional, allows C failure)

- H0 (null): No difference in cognitive burden or validation quality between A/B/C.
- H1 (C effective): C reduces cognitive burden (time + abstraction behavior) without materially degrading quality.
- H2 (burden transfer): C reduces judgment count but increases abstraction/exposure → burden transfer, not real reduction.
- H3 (C failure): C does not reduce cognitive burden or degrades quality.

**All hypotheses allowed. No preset "C must win".**

### 1.3 Participants

```
PILOT_N = 3-5
TYPE = exploratory pilot sample
CLAIM_LEVEL = PILOT / EXPLORATORY / NON-CONFIRMATORY
```

**NOT claimed**: sufficient for confirmatory statistical inference; C universal superiority; large-scale scalability; cognitive load significantly decreased; automation bias resolved.

### 1.4 Workflows (frozen from L5.7/L5.8)

| Workflow | Items | Human sees | Human does |
|---|---|---|---|
| A (Instance) | 21 | per-instance structural evidence | independent judgment (no abstraction) |
| B (Naive Pattern) | 3 | per-group, all members, no compression | commonality + comparison + prototype + boundary + judgment |
| C (Minimal Semantic) | 3 | per-claim candidate + summary + progressive disclosure | claim validation only (no abstraction) |

### 1.5 Task Materials (frozen)

- Source: `tmp/mb_phase3_2_isolated_replay_results.json` (frozen, read-only)
- 21 cases: 11 admitted / 6 region_not_formed / 4 partition_unresolvable / 2 MERGE / 0 conflict
- GT: 19 KEEP_SEPARATE : 2 MERGE (hidden from Human, scoring only)
- Generated by: `tmp/l5_7_experiment_harness.py` (reads frozen L5.5, no modification)

### 1.6 Judgment Options (same for all workflows)

```
KEEP_SEPARATE  (atoms belong to different semantic units)
MERGE           (atoms belong to same semantic unit)
UNKNOWN         (evidence insufficient to judge)
```

### 1.7 Counterbalancing

```
Latin square (3 orders):
  P1 (odd):  A → B → C
  P2 (even): B → C → A
  P3 (odd):  C → A → B
```

Assigned by participant number (P01→order1, P02→order2, P03→order3, P04→order1, ...).

### 1.8 Timing

- Per-item: recorded (start_timestamp, end_timestamp, time_seconds)
- Per-workflow: derived (sum of item times)
- Per-participant: derived (sum of all)
- No time limit (self-paced)

### 1.9 Recording (frozen schema from L5.7)

**Required**: participant_id, item_id, workflow, case_id_or_group_id, decision, time_seconds, start_timestamp, end_timestamp

**Optional**: difficulty (Easy/Medium/Hard), confidence (Low/Medium/High), order_position, expansion_count (C only), levels_viewed (C only)

### 1.10 Stopping Conditions

- Participant may withdraw at any time (partial data retained with consent)
- No forced completion (self-paced)
- Experiment ends when all 27 items (21+3+3) completed or participant withdraws

### 1.11 Limitations (frozen from L5.8, 8 non-blocking)

| ID | Limitation | Impact |
|---|---|---|
| L1 | GT imbalance 19:2 | quality statistical inference not feasible |
| L2 | Conflict = 0 | conflict-preservation Human judgment not testable |
| L3 | Automation bias 0 System≠GT | cannot test misleading claim acceptance |
| L4 | Positive all KEEP_SEPARATE | C false-acceptance not testable |
| L5 | n=21 | pilot/exploratory only |
| L6 | Learning effect (same material × 3) | counterbalanced; recorded |
| L7 | Cross-document NO | generalization not claimable |
| L8 | Single corpus | scope limited |

## 9. Human Cognitive Intervention Observation Plan [D]

### 9.1 Four-Layer Analysis

| Layer | Metrics | Source |
|---|---|---|
| 1 Operational | judgment_count, time, interaction_count, evidence_exposure | auto-recorded |
| 2 Cognitive Behavior | abstraction_behavior, revisit_behavior, expansion_behavior, difficulty | observed + self-reported |
| 3 Validation Quality | correctness vs GT, false acceptance/rejection, UNKNOWN usage | scored post-hoc |
| 4 Reusability Potential | instance→group→claim→boundary | qualitative |

### 9.2 Key Behavioral Observations

| Behavior | Definition | Expected A | Expected B | Expected C |
|---|---|---|---|---|
| ABSTRACTION_BEHAVIOR | cross-instance comparison / commonality / prototype | low | high | low (if C works) |
| REVISIT_BEHAVIOR | frequent return to previous evidence | high (21 items) | medium | low (3 claims) |
| EXPANSION_BEHAVIOR | expand beyond default (C only) | N/A | N/A | observe (if high → compression insufficient) |

### 9.3 Human Cognitive Type (H1-H4)

| Type | Description | When |
|---|---|---|
| H1 Instance Recognition | "what is this instance?" | A (primarily) |
| H2 Group Recognition | "are these a class?" | B (primarily) |
| H3 Boundary Judgment | "is this candidate's boundary adequate?" | C (ideally) |
| H4 Capability Authorization | "authorize as reusable capability?" | post-pilot (not in pilot) |

**Key question: Does C move Human from H1/H2 toward H3?**

### 9.4 N_instances → N_claims → Human Work

```
Observe:
  N_instances = 21 → N_groups = 3 → N_claims = 3 → N_judgments (A=21, B=3, C=3)

Key: N_claims → Human Work (not just N_claims → N_judgments)
  - If C.time < A.time AND C.abstraction=0 AND C.quality≥A.quality → C effective
  - If C.time ≈ A.time OR C.abstraction>0 → burden transfer
```

## 10. Failure Interpretation Rules [D]

### 10.1 C Failure Conditions

If real human data shows:

```
C judgment_count ↓ BUT
  time ↑
  OR evidence_exposure ↑
  OR abstraction_behavior ↑
  OR revisit_behavior ↑
  OR difficulty ↑
  OR quality ↓
```

→ Record: **`BURDEN_TRANSFER = OBSERVED`** or **`C DID NOT REDUCE HUMAN COGNITIVE BURDEN`**

### 10.2 What NOT to do if C fails

```
DO NOT modify:
  - Aggregation primitive
  - Compression primitive
  - UI presentation
  - Claim wording
  - Workflow definition
  - Task definition
  - GT / TLD / Atomic Observation / IS-11 / production code

DO NOT "fix" C to make it succeed.
```

### 10.3 What TO do if C fails

```
DO:
  - Record as observed failure (real human evidence)
  - Report honestly
  - Identify specific failure mode (burden transfer / quality degradation / etc.)
  - Note as potential future research question (requires separate authorization)
```

### 10.4 Quality Analysis Caution

```
GT = 19:2 (SEVERELY IMBALANCED)
conflict = 0
System ≠ GT = 0

Therefore:
  - If all participants agree with GT → write: "No material validation-quality degradation observed within pilot material"
  - Do NOT write: "C improves accuracy"
  - False acceptance coverage = limited (2 MERGE cases only)
  - Automation bias evidence = limited (0 System≠GT)
```

**Failure Interpretation Rules = READY**
